# Reporting Contract

## Append-only, assembled once

Findings are written **one small JSON file at a time** to
`<RunDir>\findings\<id>.json`, using `assets/finding-template.json` as the shape.

`REPORT.md` and `audit-state.json` are then generated by
`scripts/assemble-report.ps1`. Do not write either of them by hand.

```powershell
.\assemble-report.ps1 -RunDir '<run>'            # generate
.\assemble-report.ps1 -RunDir '<run>' -Validate  # check findings, write nothing
```

Run the assembler at `FINAL_VALIDATION`, and before a reboot checkpoint. Not
after every finding: there is no reason to, and regenerating a growing report
inside the model costs the entire report in output tokens plus the entire report
again as input on the next turn.

The assembler refuses to silently accept:

- an `action` or `critical` finding with no `recommended_action` and no
  `remaining_uncertainty`;
- a finding with `confidence: UNKNOWN` and no `remaining_uncertainty`.

Those two rules exist because that is exactly how audits quietly end with
unresolved items presented as complete.

## Deliverables

- `REPORT.md` - generated. Human-readable findings and scoreboard.
- `audit-state.json` - generated. Machine-readable state, findings, approvals.
- `REMEDIATION-LOG.md` - hand-maintained, append-only. One entry per mutation.
- `RESUME.md` - only while a reboot or handoff is pending.
- `findings/*.json` - the source of truth for the first two.

## Finding states

| state | glyph | meaning |
|---|---|---|
| `healthy` | white check | verified healthy |
| `observe` | yellow circle | observe / intentional / validation pending |
| `action` | orange circle | action recommended |
| `critical` | red circle | critical |
| `historical` | white circle | historical / noise / informational |

Set `initial_state` when a finding's state improves, so the dashboard can show
initial versus final honestly. Never downgrade severity to make the final
dashboard look better.

## Remediation log entry

Every mutation, appended at the time it happens:

- timestamp;
- finding ID;
- before state;
- exact action or command;
- approval reference;
- reason;
- result and exit code;
- after-state verification;
- rollback path if applicable.

## Final verdict

Summarize, in this order:

1. overall health;
2. verified strengths;
3. unresolved critical and action items;
4. intentional deviations;
5. historical/noise items that should not trigger cargo-cult fixes;
6. performance headroom;
7. deferred cleanup choices;
8. items deliberately deferred to stay within budget, named explicitly;
9. `UNKNOWN` items and their next discriminating test.

Item 8 is not optional. An audit that quietly stopped early is worse than one
that says which stone it left unturned and why.
